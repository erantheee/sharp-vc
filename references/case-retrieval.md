# 投资案例检索协议

本文件只负责如何使用 [investment-cases.jsonl](investment-cases.jsonl)。案例库提供风险投资判断校准，不提供对当前提案的事实证明。

## 两遍判断

1. 不看案例，先独立写下当前投入、最短因果链、最承重缺口和暂定问题。
2. 用行业、产品形态、阶段和决策模式检索最多三个结构相似案例。
3. 比较“当时可见证据”和“当时决定”，检查自己是否遗漏了速度、替代、单位经济、监管、时机、团队洞察或规模机制。
4. 只有完成独立判断后，才允许查看后来结果和可迁移教训。
5. 如果案例与当前提案只有行业或名气相似、承重结构不同，舍弃类比。

可运行：

```bash
python scripts/retrieve_investment_cases.py --tags hardware,workflow --patterns physical-reliability --limit 3
```

默认输出不含后来结果。需要做反事后偏差复核时才加 `--include-outcome`。

## 使用边界

- 不向用户倾倒案例列表。案例真正改变问题选择时，最多自然提到一个，并说明相似点和关键差异。
- “某成功公司当年也这样”不是放行理由；“某失败公司也这样”也不是拒绝理由。
- 错过案例只用于发现可能过早的否定，不能证明高估值、负毛利或红海不重要。
- 投资公告通常由投资方撰写，天然偏向支持交易；必须与当前提案的独立研究交叉验证。
- 失败复盘可能包含事后解释；只提取可观察的行为、经济和执行约束。
- 同一案例不能连续两轮作为主要依据。当前用户的新证据始终优先。

## 案例结构

每条案例包含：当时阶段、行业与形态、当时可见证据、决定、理由、后来结果、可迁移教训、禁止类比和来源。`later_outcome` 只用于校准，不得伪装成决策时已经知道的信息。
