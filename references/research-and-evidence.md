# 研究与证据协议

研究的目的，是找到第一道最有价值的问题，不是展示资料数量。

## 一、研究底稿

先把“市场”拆成四层，不能混为一个结论：

1. **问题市场**：一群人是否高频遭遇有后果的问题。
2. **品类市场**：用户是否已经为解决这类问题付费，是否存在持续经营、收入、复购、众筹付款、企业采购或并购。
3. **产品形态市场**：用户是否愿意采用并支付用户提出的这种具体机制、硬件形态与交互方式。
4. **可经营市场**：在目标价格、渠道、毛利、交付和售后条件下，提案人是否能够获得这部分需求。

问题市场成立，不能自动推出品类市场；品类市场成立，也不能自动推出具体产品形态成立。但具体形态未验证时，必须保留并明确说出已经被证明的品类潜力。

根据提案实际相关性，覆盖：

1. 直接竞品：能力、价格、目标人群、渠道和已知限制。
2. 替代方案：不购买、人工处理、通用工具、低价方案和相邻品类。
3. 需求证据：实际行为、问题频率、后果、持续使用、付费、退货或放弃原因。
4. 商业约束：可触达渠道、定价参照、毛利结构、积累时间和售后负担。
5. 技术与外部约束：关键性能、成本、可靠性、法规、权限或供应链。

研究时必须主动寻找两组证据：

- **机会信号**：仍在销售的产品与价格、真实付款人数、收入、续费或持续使用、企业采购、融资并购、明确替换行为。
- **方案风险**：低价替代、用户放弃或退货、使用中断、效果边界、成本与售价冲突、安全和售后负担。

不能只搜负面证据来证明自己尖锐，也不能只搜市场规模来证明机会。先把最强的机会版本立住，再攻击用户的具体产品形态。

不相关的维度不要机械扩展。研究停止条件是：每条会改变第一道问题的外部承重主张，已经获得一手或权威来源；在合理可得时，再有一个独立来源交叉验证。找不到时记录“未知”，不要无限搜索。

## 二、来源优先级

- 能力、规格、价格、政策：官方产品页、官方文档、监管机构或标准组织。
- 学术与技术可行性：原始论文、标准、官方技术文档。
- 用户行为与商业表现：可核实交易或使用数据、公司披露、独立研究；评论和论坛只能作为线索或个案。
- 新闻和二手分析：用于补充上下文，不替代可获得的一手来源。

时间敏感信息必须现场核验。引用应紧邻其支持的判断。不得用搜索结果摘要代替打开和阅读来源。

## 三、证据标签

对内部账本中的关键主张可以使用：

- `F 已核验事实`：可靠来源直接支持，注明日期和来源。
- `C 计算`：基于已列明输入的推导，写清公式和输入。
- `E0 设想`：直觉、故事或理论可能性。
- `E1 个案`：个人经历、少量访谈或单个案例。
- `E2 代理证据`：竞品、搜索、相邻品类或问卷，只能支持方向。
- `E3 行为证据`：目标用户在真实或高保真场景持续表现出问题或采用方案。
- `E4 付费证据`：订单、订金、续费、留存或可核实的替换购买。
- `U 未知`：没有足够信息判断。

来源可靠只说明“某事实存在”，不自动把商业主张提升到 E3 或 E4。竞品有功能可以证明能力存在，不能单独证明用户会为新差异付钱。

这些代码不得出现在用户可见输出中。对外翻译为：

- `E0` → 目前只是设想；
- `E1` → 只有个人、访谈或论坛个案；
- `E2` → 有竞品、相邻品类或其他间接信号；
- `E3` → 已有可观察的真实使用行为；
- `E4` → 已有订单、订金、续费或其他真实付款。

## 四、保密与检索

- 默认用泛化品类、问题和技术类别检索，不使用用户的未公开产品名、逐字原文、客户名、内部数据或独特机制。
- 不向外部服务上传原文或附件。
- 如果精确核验必须暴露未公开细节，先说明要查什么、为什么泛化检索不够，并获得用户明确许可。
- 用户声明不得联网时，完全基于其材料工作并标记 `研究状态：未核验`。

## 五、对用户的呈现

研究完成后不要先输出长报告，也不要套用“先说结论”“一句话结论”等固定开场。第一次判断应自然覆盖：

```
用自然语言直接说明当前最诚实的判断；
给出真实付款、收入、持续使用、在售产品或其他最强机会信号；
说明机会目前成立到问题、品类、产品形态或可经营市场中的哪一层；
指出具体方案不能跨越的证据断点及其商业影响；
说明什么行为、付款、阈值或实验会改变判断；
最后只留下一个能推进决策的问题。
```

如果没有找到机会信号，也要写“尚未找到真实付款或持续使用证据”，不能用沉默暗示已经查过且市场不存在。

“研究完整 / 不完整 / 未核验”是内部状态。只有状态会影响用户对结论的理解时才自然说明，例如“我没有找到该品类的可靠销量，因此这里仍有证据缺口”，不要机械输出 `研究状态：` 字段。

如果第一问只是确认项目类型，可以省略判定；仍可简要说明研究为何使类型存在歧义。
